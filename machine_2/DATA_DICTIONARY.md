# Data Dictionary: Coordination Tax Benchmark Dataset

This document provides complete descriptions of the files, fields, and metrics included in the Mendeley Data deposit for the study:
*"When Does Role-Based Collaboration Beat Compute-Matched Sampling? A Framework-Controlled Study of Multi-Agent LLM Orchestration on Resource-Constrained Local Hardware."*

---

## 1. Directory Structure of Mendeley Deposit

```text
mendeley_deposit/
├── README.md                          # Comprehensive dataset overview & replication guide
├── DATA_DICTIONARY.md                 # This file
├── tasks/
│   ├── tasks.json                     # 132 benchmark tasks across domain categories
│   ├── corpus.json                    # Local domain knowledge corpus for retrieval
│   └── calibration_tasks.json         # Standardized hardware calibration tasks
├── raw_data/
│   ├── condition_A.jsonl              # Single ReAct Agent baseline (150 runs)
│   ├── condition_B.jsonl              # Compute-matched Best-of-N sampling (150 runs)
│   ├── condition_C.jsonl              # LangGraph multi-agent orchestration (150 runs)
│   └── condition_D.jsonl              # CrewAI multi-agent orchestration (150 runs)
└── statistics/
    ├── statistics_report.json         # Primary statistical tests & effect sizes
    └── mechanism_report.json          # Tool diagnostic & overhead breakdown
```

## 2. Raw Execution Records (`raw_data/condition_*.jsonl`)

Each line in the `.jsonl` files represents a single task execution record structured as a JSON object:

| Field Name | Data Type | Description |
|---|---|---|
| `task_id` | String | Unique identifier of the benchmark task (e.g., `task_042`) |
| `condition` | String | Experimental condition (`A`, `B`, `C`, or `D`) |
| `machine_id` | String | Identifier of the machine that executed the run (`machine_1` through `machine_4`) |
| `config_hash` | String | SHA-256 hash of `config.yaml` ensuring identical evaluation settings (`e4da2c9abab2`) |
| `output` | String | Final text response generated by the agent / framework |
| `total_tokens` | Integer | Cumulative token consumption (prompt + completion tokens) |
| `prompt_tokens` | Integer | Total prompt tokens processed across all LLM calls |
| `completion_tokens` | Integer | Total completion tokens generated across all LLM calls |
| `latency_seconds` | Float | Wall-clock execution time in seconds |
| `tool_calls` | Integer | Total number of tool invocations performed during task execution |
| `score` | Float | Binary or graded task accuracy score evaluated by judge model (`0.0` or `1.0`) |
| `judge_reasoning` | String | Explanation provided by the judge model for the given score |
| `timestamp` | String | ISO 8601 timestamp when the task execution completed |

## 3. Benchmark Task Definitions (`tasks/tasks.json`)

The benchmark comprises 132 tasks stratified across domain categories:

| Field Name | Data Type | Description |
|---|---|---|
| `id` | String | Task identifier matching raw record `task_id` |
| `category` | String | Task domain category (e.g., `multi_step_reasoning`, `fact_retrieval`, `synthesis`) |
| `prompt` | String | Input prompt provided to the agent/framework |
| `gold_answer` | String | Ground-truth reference solution used for judge evaluation |
| `difficulty` | String | Human-assigned difficulty rating (`easy`, `medium`, `hard`) |

## 4. Local Corpus (`tasks/corpus.json`)

Contains the local domain corpus used by retrieval tools during benchmark runs:

| Field Name | Data Type | Description |
|---|---|---|
| `doc_id` | String | Document identifier |
| `title` | String | Section or document title |
| `text` | String | Full text content available for local agent retrieval |

## 5. Statistical Reports (`statistics/`)

### `statistics_report.json`
- **`paired_differences`**: Condition pairs (B vs A, C vs A, D vs C, D vs B) with accuracy delta, 95% confidence intervals, and p-values.
- **`effect_sizes`**: Cohen's $d$ and Hedges' $g$ effect size metrics across condition pairs.
- **`stratification`**: Machine-class stratifications across hardware tiers.

### `mechanism_report.json`
- **`tool_diagnostics`**: Frequency, error rates, and binding execution for condition tools.
- **`overhead_breakdown`**: Token overhead and framework latency tax ($5,358.5$ token framework overhead for Condition D).
